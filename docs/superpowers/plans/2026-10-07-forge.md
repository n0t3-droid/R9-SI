# R9 Forge — icon-driven architecture generators · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 🏢 🏠 🌉 🗼 🏛 🏰 🚀 🌳 🧱 (🏟) — a short DNA string becomes a walkable, furnished structure, deterministically, in the Studio's worker and in the game's worker, and a plan `{kind:'forge', dna}` places it into a world.

**Architecture:** `src/shared/forge*.js` hold the core (types, DNA ↔ params, German text parser, variants, tweak) and one generator grammar per type, all writing into one grid format `{sx,sy,sz,blocks:Uint16Array,dy}` (0xFFFF = keep world). The Studio worker meshes a grid for previews/ghosts (`place_mesh` kind `forge`), the game worker turns a grid into lot-local ops (`forge` job); `blueprints.js` builds the ops with terrain levelling or piers and in slices per frame. `src/studio/forge.js` is the 🏭 Forge mode (icons, text, 3×3 variants, sliders, 📍 Setzen / 🧩 Als Bauteil).

**Tech Stack:** plain ES2019 in the project's IIFE style, node tests (`test/load_shared.js`), sharp for sheets, Playwright for the browser test.

**Spec:** the task brief (this plan's header), `docs/superpowers/specs/2026-10-03-live-loop-design.md` (plan kind `forge`, DNA as ref), `2026-10-07-all-ages-workflow-design.md` §5 (the ✨ wizard runs the Forge behind Was?/Wie?/Wohin?).

## Global Constraints

- No new block ids. Compose from existing blocks, VX blocks and VM models (Modern Living included).
- Deterministic from `(type, params, seed)`: the same DNA → the same grid, in every thread.
- Generators live in `src/shared` (SHARED and STUDIO_MAIN in build.js); no DOM, no `VR.HouseKit`, no `VR.GenieBrain` dependency (used only when present).
- Build budget: a `tower:f32,w30,d30` (30×160×30) builds in ≤ 1 s in node; plans > 60 000 changed cells are applied in slices (≤ 24 000 per tick).
- Grid: `{sx, sy, sz, blocks: Uint16Array[(y*sz+z)*sx+x], dy}`; world y = F + dy + gy; lot-local u = x, v = z; the front (street side) is v = 0; the anchor is the front centre `[sx >> 1, 0]`.
- German icon-first UI; strings via `VR.I18N.tx` when present, plain German otherwise. No README/ROADMAP edits.
- Studio edits limited to: new `src/studio/forge.js`, small hooks in `world.js`, `studio_worker.js`; the nav button is injected at runtime (no header edit).

## Review Focus

1. A DNA with out-of-range or unknown tokens (`tower:f999,zzz`) must build (clamped to the ranges, unknown ignored), never throw.
2. A bridge placed with one end on a hill: the deck stays level at F, piers never go below `ground`, and nothing is written below `F - 48` (the game's box depth).
3. A tower with `f80,w40,d40` (≈ 640 k cells) must stay under 16 MB per message and build in slices without freezing the frame (no single `applyEdit` > 24 000 cells).
4. `Forge.fromText` with no recognisable type ("blau") returns `null`, with a type but nonsense numbers returns the defaults.
5. The Studio with no world open: 📍 Setzen tells the user to open a world (◍ Welt) and 🧩 Als Bauteil still works.

**Interfaces:**
- Produces `VR.Forge`:
  - `Forge.types` — ordered array `[{id, icon, name, params:[{k, label, min, max, def, step?, words?:[..]}], styles:[{id, name}], flags:{level, terrain, front}}]`; `Forge.type(id)`.

- Consumes: `VR.RNG`, `VR.R.byName`.
