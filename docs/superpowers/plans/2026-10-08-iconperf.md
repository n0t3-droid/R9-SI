# Plan: the ✨ Modern Living tab opens without a hitch (iconperf)

## Measured (v0.40, browser, 236 items; probe run through test/wt_run.sh, now removed)
- One palette frame held 203 ms of icon work: `vm_garden_hammock_stand` 188 ms in its lazy build (`materialize`) and
  10 ms in `VM.icon`. Next: fridge 79 ms (build 27 + icon 33), rattan divider 56 ms (build 51).
- All icon paints: 2.0 s in total = builds 0.95 s + `VM.icon` about 1.0 s + drawing.
- `VM.icon` (src/shared/voxmodel.js) samples the whole span³ box through `m.get`, once per icon: up to 16 M calls for a
  large model. Node: 843 ms for the 236 items.
- `Builder.extrude` (src/shared/voxmodel.js) runs the point-in-polygon test for every voxel of every layer. The 2-D
  result does not depend on the layer: the hammock (168 edges, 6 layers) makes 2 M edge tests.
- The lazy build runs synchronously on the first paint of a model, with no budget (since v0.40 the pack is no longer
  built at boot, which is why the tab got slow; at v0.39 the pack was built before the tab opened).
- `VX.init` is not the cause (0 ms, already done at world creation). `Icons.face()` is not used by the tab (0 paints).
- Studio 🧱 Teile ✨ Modern chip (v0.40 build, Studio probe, 236 cards): the first 6 visible thumbnails took 605 ms, the
  slowest 198 ms; frames up to 325 ms, 5 over 50 ms. The build share of those thumbnails is 6 ms, so the lazy build is
  not the cause here. Node, all parts of all 236 models: `VX.meshGridN` takes 5.6 s in all (median 12 ms per model,
  p90 57 ms, worst garden_outdoorkitchen_grill 518 ms, which has several parts). Each Studio thumbnail meshes every part.

## Root causes
1. `VM.icon` visits every empty cell of the span box. It only needs the occupied voxels.
2. `Builder.extrude` repeats the 2-D inside test per layer.
3. A model's first paint builds the model synchronously with no budget (the hammock: 188 ms in the browser).
4. Studio thumbnails (studio/studio.js `thumbOf`): the mesher runs once per model part at 32 res, then a GPU read-back.
   Each thumbnail costs 40–200 ms on this machine; the chip makes them in its own frames.

## Changes (each keeps every voxel and icon cell; test/icon_same.js holds the reference)
- A. `VM.icon`: one pass over the model's voxels into the 8³ bins (same sums, flags and threshold). The sampling loop is
  kept as the fallback for a grid that is not integral.
- B. `Builder.extrude`: the inside mask is computed once per call and reused for every layer.
- C. `VR.IconPump` (src/main/icons.js) replaces the ad-hoc pump in ui.js: a frame paints until 6 ms are used (the check
  comes before each paint); a model still to be built is one such paint; detached canvases are skipped without cost.
  A first version gave every cold model a frame of its own. That made a cold tab of 236 models take 236+ frames
  (about 4 s at 60 fps), so it was dropped once the builds were at most ~13 ms each.
- D. `VR.iconWarm` (src/main/icons.js): idle-time pre-warm of the Modern Living pictures through VM.prewarm, one per
  idle slice, largest first, never before 10 s of play (started with the model pre-warm in game.startPrewarm). It stops
  while the page is hidden and starts again when the page shows.
- E. `VR.warmQueue` (src/main/icons.js): the same idle queue for any list of ids (build once per id, in the order given).
- F. Studio 🧱 Teile ✨ Modern chip (src/studio/catalog.js): the Modern thumbnails are made in idle time through
  `VR.warmQueue`, 10 s after the Studio is up, into `C.THUMB`, the cache the chip reads. The chip's own pump is unchanged.
  The root cost (the per-part mesher, `VX.meshGridN`, shared with the world's meshing) is not changed here: a faster
  mesher needs the output held identical (test/mesh_same.js, gen_same.js) and is a follow-up.

## Known gaps
- The Studio thumbnail cost is the mesher (`VX.meshGridN` once per model part). The idle warm makes one thumbnail per
  idle slice, and a thumbnail is not divisible, so one idle slice can still run up to the worst thumbnail's time.
- SwiftShader: frames take seconds on this machine, so a frame count says little here; the icon work per frame is the
  measure. The tab's wall time on this machine is dominated by the rendering.
- The idle warm runs only while the page is idle. A cold tab (opened within the first seconds of play) still paints
  its pictures through the pump.
- First use in a session still pays the build of each model (at most ~13 ms in node).
