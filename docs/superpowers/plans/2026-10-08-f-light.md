# F1 · Licht & Luft — plan (branch f-light, based on v041)

Spec: docs/superpowers/specs/2026-10-08-realism-wave-design.md, section F1. Rules that hold here: the Very Low
(potato) preset gets faster or stays equal; block ids untouched; the mesher and light reference tests stay green
unless a proof and a new reference come with the change; every player-facing text through VR.I18N; no external
requests; every test ends with ALL OK / FAILED n.

## What, in cost tiers

Preset → tier: potato = Very Low (T0), low (T0.5), balanced (T1), high (T2), ultra (T3).

| Effect | Very Low (potato) | Low | Balanced | High / Ultra |
|---|---|---|---|---|
| Sky (Perez-style luminance + own xy fit, twilight, moon phase, stars) | 64×32 LUT, rebuilt when the sun moved ~0.5° | analytic per pixel | analytic | analytic |
| Sky pass | drawn after the opaque terrain, depth-culled (only sky pixels shade) — all tiers | | | |
| Sun disc | limb darkening, bloom halo | same | same | same |
| Aerial perspective (replaces flat haze) | per-channel transmittance, in-scatter from the LUT | analytic | analytic | analytic |
| Shadows | no cast map today (kept: cost) | none | PCF 3×3, 1024 map | rotated poisson (16 taps), 2048 / 3072 map, near cascade 24 blocks |
| Slope-scaled bias | — | — | yes | yes |
| Cloud shadows on ground | — | — | 2D noise lookup | same |
| Vertex AO | stronger mapping (1 − k·occluders) | same | same | same + screen-space AO |
| Screen-space AO | — | — | — | 8 taps, half res, bilateral upsample |
| Exposure | GPU running average (1×1, eased, ±stops clamped) — all tiers | | | |
| Grade per time of day | lift / gain per time (dawn warm, dusk magenta, night blue) — all tiers | | | |
| Vignette | lighter (0.3, was 0.55) — all tiers | | | |

Things the spec asks for that are not in this wave's code path and stay open (listed in the report): window glow
from the interior light field (needs a spare bit in the vertex format), block-light colour by source (needs bits in
the light field), mesher-level overhang AO (changes mesh_same's reference), contact hardening (PCSS blocker search).

## Order (each step: failing test first, small commit)

1. Measurement hooks: `renderer.prof` (off by default) puts a `gl.finish()` and a timer around each pass;
   test/light.mjs measures the fixed scene. Baseline numbers are taken on the unchanged v041 code.
2. Sky model in src/main/atmos.js (VR.Atmos): node test test/atmos.js (sun at noon > dusk, dusk orange,
   night dark blue, LUT within 2 % of the formula, exposure easing).
3. Sky shader: analytic base + LUT path, sun disc with limb darkening, moon phases, stars fade at dawn; sky pass
   moved after the terrain (depth-culled).
4. Aerial perspective in applyFog (per-channel transmittance, in-scatter from the sky radiance).
5. Exposure (GPU running average) + grade per time of day + lighter vignette in the composite.
6. Shadows: PCF 3×3 (balanced), rotated poisson (high), slope-scaled bias, cloud shadows; hard 1-tap map only if
   Very Low's total cost stays at or below the baseline (measured, otherwise not added).
7. Vertex AO mapping (stronger with occluders), then SSAO on high (half res, 8 taps, bilateral upsample).
8. Near cascade on high/ultra (24 blocks), if the budget allows.
9. Screenshots (test/shots/light_*.png) at 06:00, 12:00, 18:30, 23:00 outdoors and inside a lit house, Very Low and
   High; looked at, and iterated.
10. Regression: node tests, REGRESS_ONLY=node regress, classic_v2.mjs, smoke.mjs, atmosphere.mjs, light.mjs.

Times in the game: ticks 0 = 06:00 (sunrise), 6000 = 12:00 (noon), 12000 = 18:00 (sunset), 18000 = 00:00.
So 18:30 = 12500 and 23:00 = 17000.

## How it is measured

Fixed scene: default world, seed 1, the Heartland plaza near the spawn, 12:00 (ticks 6000), frozen time, 1280×720,
Very Low and High, averaged over 8 frames after the chunks settled. Per pass (ms, `gl.finish()`-bounded, i.e. the
real SwiftShader work, relative costs only): sky, shadow, terrain, horizon, objects, copy, clouds, trans, precip and
particles, hand, tsr, post. Also draws, tris, sections, shadow draws and the number of full-screen passes.

Toggles for the per-effect "off / on" numbers come from the renderer's own flags (q.*), not from new code paths.
